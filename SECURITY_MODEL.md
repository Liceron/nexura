# Nexura security model

Status: first version (2026-10-14), not externally audited. It states what is enforced today, where, and which test proves it. Anything not listed as covered is not covered. Report vulnerabilities as described in [SECURITY.md](SECURITY.md).

Proof tests: `tests/security/test_secure_defaults.py` (this document's own tests) plus the existing suites named below.

The MIT open-source edition is **single user, this machine only; for a team or a public endpoint use the hosted or enterprise edition**. Every REST request is the local owner (`local-owner`, role `admin`); `X-Principal-ID` and `X-Principal-Role` are ignored. Local workspaces are project folders, not separate users or tenants. The unsafe network opt-in adds no authentication. "This machine only" holds for the CLIs and for embedding: `create_api_app()` (and Studio's `create_app()` without a token) answers 403 `NON_LOOPBACK_CLIENT` to any peer that is not loopback, even when an embedding app runs it with `uvicorn.run(app, host="0.0.0.0")`, unless the operator gives the insecure opt-in. State-changing requests also need the per-session token (`X-Nexura-Session`), so a web page in a local browser cannot drive the service. The one supported remote use is remote single-operator mode (`nexura-runtime serve --auth token`, [docs/remote-single-operator.md](docs/remote-single-operator.md)): the same single owner, with one operator token on every request, behind a TLS reverse proxy. It adds no accounts, roles or per-user audit; those stay in the enterprise edition.

## 1. Assets

| Asset | Where it lives |
| --- | --- |
| Workflow definitions, run state, checkpoints, chat history | SQLite (`nexura_service.sqlite3`, created 0600 on Linux and macOS; on Windows the file inherits the folder's ACL, so keep the data folder private) |
| Credentials and webhook signing secrets | scoped credential store, trigger secretbox |
| Host process privileges and filesystem | whatever runs `nexura-runtime serve`, the worker or a registered handler |
| Provider API keys and environment variables | process environment |
| Approval decisions | run store |
| Resource separation between local workspaces (one owner) | workspace repository |

## 2. Trust boundaries

1. Network client to REST service or Studio server (HTTP).
2. Browser origin to API (DNS rebinding, CSRF).
3. Workflow spec (data) to runtime (registered handlers only).
4. Runtime to MCP server (stdio child process or HTTP).
5. Model output to tools (prompt injection).
6. Sandbox worker to host.
7. Operator-registered handlers and `--handlers` sources: trusted code, outside the model.

### 3.3 Prompt-injected model

| Threat | Control and where | Proof | Status |
| --- | --- | --- | --- |
| Injected text makes the model call a dangerous tool | a tool with `requires_approval` pauses; SDK resume binds reviewed digests or verifies a signed/stored envelope, enforces expiry and atomically consumes grants with a configured approval/checkpoint store; side-effecting tools are not auto-retried; guardrails | `tests/p35/test_a2_approvals.py`, `tests/agents/test_audit9_security_fixes.py`, approvals suites | PARTIAL: approvals are opt-in per tool (a plain `@tool` function is not gated unless it sets `requires_approval=True`; the SDK cannot tell that arbitrary Python writes externally); there is no automatic taint tracking |
| A client alters, expires or replays an SDK `RunInterruption`, or `approve=True` certifies a substituted action | Runner defaults to a one-hour `approval_ttl`; checks stored action digests and transcript; optional `approval_signing_secret` authenticates canonical full-envelope JSON with HMAC-SHA256 (run, starting/active agent, call ids, tool names, argument digests, expiry, transcript and state). TeamInterruption has a separate authenticated envelope covering its name, original and nested prompts, completed outputs/text/usage and full pending member envelopes, with expiry at the earliest member deadline. ## 4. Explicitly not covered yet

- Studio web (`studio-web`) sends a token only if you type one into Connection Settings ("Service Auth Token"). It is held in memory for the session (not persisted, lost on reload) and sent as `Authorization: Bearer <token>` through the TypeScript client (`apiKey`), which the older built-in Studio token middleware accepts. The open-source REST service has no user authentication and ignores this bearer, so the field gives no protection there; what protects the REST service from other web pages is the per-session token, which Studio reads and sends by itself (section 3.1). Nothing is sent when the field is empty. Proof: `test_studio_web_sends_connection_token_as_bearer` (`tests/docs/test_docs_audit10.py`, a source check of `studio-web/src/api/client.ts` and `clients/typescript/src/client.ts`) and `test_studio_token_is_enforced_when_configured`. There is no browser-level test of the settings form.
- MCP child processes inherit the whole environment; there is no environment scrubbing.
- No request rate limiting or per-workspace quotas (remote single-operator mode limits only failed token attempts per address); no TLS termination in the service. A reverse proxy does not add multi-user support to the OSS edition.
- The gVisor sandbox has had no external review; there is no fuzzing. The closed edition separately documents its unaudited shared profile.
- Operator-registered handlers, `--handlers` sources and installed plugins are fully trusted code.
- Mock-transport tests do not prove behaviour against live providers.

## Review hardening (P1)

- `nexura-runtime serve` passes `--host` to `create_api_app(listen_host=...)`; a non-loopback host without authentication exits with code 2 and a clear message. The only opt-out is `--insecure-allow-unauthenticated-network` or the documented environment variable. Tests: `test_cli_serve_refuses_non_loopback_without_auth`, `test_cli_serve_loopback_starts`, `test_cli_serve_explicit_insecure_flag_allows_network_bind`. `nexura-runtime worker` binds no port and is not guarded. When `listen_host` is omitted but `bound_host` is given, `bound_host` is checked (`test_service_bound_host_is_used_when_listen_host_missing`); with neither, loopback is assumed.
- Studio request-body caps: workflow import uses `max_import_body_bytes` if given, otherwise 40 MiB when the general cap is default, otherwise the smaller of the general cap and 40 MiB. Tests: `test_studio_body_cap_applies_to_import_path`, `test_studio_import_default_cap_is_larger_than_general_cap`. A malformed `Content-Length` no longer yields a 500 (`test_studio_invalid_content_length_not_500`).

## Local master-key text

`StaticMasterKeyProvider.from_text` decodes strictly (url-safe alphabet, 32 bytes, no whitespace) and never echoes the text. Proof: `test_master_key_text_is_strictly_decoded` (`tests/test_local_encrypted_secrets.py`). Organisation invites and master-key rotation are closed-edition features.
